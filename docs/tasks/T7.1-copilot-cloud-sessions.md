# T7.1 — Copilot cloud agent sessions

Status: proposed, not started. Read AGENTS.md "Reporting and dashboard" first;
this task changes that contract (see "Contract changes") and must not start
until the owner signs off on those changes.

## Goal

Report GitHub Copilot cloud agent sessions (the ones started from
github.com, an issue assignment, or `gh agent-task create`, which run on GitHub
Actions runners) to the dashboard with metadata and full transcripts. Today the
daemon only finds providers that leave files on the local disk
(`internal/daemon/providers.go`), so these sessions never appear.

## What we know (checked 2026-10-13, gh 2.102.0)

All of this is preview surface. GitHub labels `gh agent-task` "in preview and
subject to change without notice". Treat every shape below as observed, not
documented.

- `gh agent-task list|view` calls `https://api.individual.githubcopilot.com`
  with the normal `gh auth token` as a bearer token. Enterprise and business
  accounts likely use a different host; confirm before assuming `individual`.
- IDs: the web URL `github.com/<owner>/<repo>/tasks/<task id>` shows a *task*
  id. A task has one or more *sessions* (follow-ups add sessions). `gh
  agent-task view <task id>` fails with "session not found"; it wants a
  session id. Map with the session's `task_id` field.
- `GET /agents/sessions` lists the caller's sessions, newest first (what `gh
  agent-task list` uses). Some sessions come back with no repository or pull
  request attached; `repo_id` is still set.
- `GET /agents/sessions/{id}` returns JSON with, among others: `id`,
  `task_id`, `agent_task_id`, `state` (`queued`, `in_progress`, `idle`,
  `completed`, `failed`, and probably `cancelled`), `model`, `repo_id`,
  `owner_id`, `user_id`, `head_ref`, `base_ref`, `created_at`,
  `last_updated_at`, `completed_at`, `workflow_run_id`, `premium_requests`,
  `ai_credits`, `name`, `error`, `resource_type`/`resource_id` (the pull
  request), `logs_blob_id`, `events_blob_id`.
- `GET /agents/sessions/{id}/logs` returns `text/event-stream`: one `data:
  {json}` line per record, blank-line separated. A completed session of about
  four minutes was 109 records, 230 KB. Two record shapes were seen:
  - Chat completion chunks: `{id, object, created, model, choices: [{index,
    finish_reason, delta: {role: "assistant", content, tool_calls: [{id, index,
    type, function: {name, arguments}}]}}]}`. Observed tool names include
    `bash`, `view`, `glob`, `rg`, `apply_patch`, `report_progress`,
    `run_setup`, `web_fetch`, `parallel_validation`, and `github-mcp-server-*`.
  - Tool results: `{role, content, tool_call_id, toolTelemetry: {properties,
    metrics}}`.
  The original problem statement was not obviously in the stream; check
  `event_content` on the session or the task before assuming it is lost.
- Repository name: `GET https://api.github.com/repositories/{repo_id}`
  (documented REST) gives `full_name`.

## Approach

### Fetching

New package `internal/transcript/copilotcloud`. Network access stays out of
the parser:

1. A small client (`client.go`) with an injectable `http.Client`, base URL, and
   token source. The token comes from `gh auth token` run with an argument
   array and a timeout. Never log, persist, or print the token. Bound every
   request with a timeout and a maximum body size.
2. A fetcher lists sessions, filters to allowlisted repositories, and writes
   each session's `/logs` body to a local cache file
   `~/.firekeeper/cloud/copilot/<session id>.sse` (directory 0700, file 0600),
   plus a small `<session id>.json` with the session object. Only rewrite a
   cache file when the remote body is longer than or differs from the cached
   one.
3. The `TranscriptSource` then reads the cache file exactly like the local
   JSONL sources: byte offsets, `seq` = index of the `data:` record. Locate
   returns the cache path. This keeps `state.json` keyed by absolute path, so
   the reporter's offset and truncation logic needs no change.

Recommendation for the first version: only fetch sessions whose state is
`completed`, `failed`, `cancelled`, or `idle`. We have not confirmed that a
live session's earlier records never change; if they do, `seq` stops being
stable. A follow-up can test `in_progress` sessions by fetching the same
session twice and comparing prefixes.

### Parsing into normalized events

| Record | role | text | other fields |
| --- | --- | --- | --- |
| chunk with `delta.content` | `assistant` | content | `model` from the chunk |
| chunk with `delta.tool_calls` | `tool_call` | `function.arguments` | `tool_name` = `function.name` |
| `{role: "tool", tool_call_id}` (or any `tool_call_id`) | `tool_result` | `content`, truncated at 64 KiB | |
| anything else, unparseable JSON | `meta` | empty | |

If one chunk has both content and tool calls, decide whether to split it.
Splitting breaks "one record per source line"; prefer one event with role
`assistant` and the tool call kept in `raw`, unless the dashboard needs
`tool_name`. Write the decision in `NOTES.md`. Every record goes through
`internal/redact`; `toolTelemetry.properties.command` and `inputs` hold
command lines and must be redacted like any other text.

### Session metadata

| Field | Source |
| --- | --- |
| `session_id` | session `id` |
| `provider` | see "Contract changes" |
| `cwd` | empty, or `github.com/<full_name>` |
| `project` | repo name from `full_name` |
| `branch` | `head_ref` |
| `model` | session `model` |
| `state` | `queued`/`in_progress` → `ACTIVE`, `idle` → `WAITING`, `completed`/`failed`/`cancelled` → `ENDED`, other → `UNKNOWN` |
| `title` | `name`, else the pull request title |
| `started_at` / `last_activity_at` | `created_at` / `last_updated_at` (or `completed_at`) |
| tokens | not exposed; leave zero. Do not show `premium_requests` as tokens. |

## Contract changes (need sign-off first)

1. **Provider value.** The normalized event enum (`docs/event.schema.json`,
   `internal/transcript/event.go`, AGENTS.md) allows only `codex | copilot |
   kimi | claude`. Proposed: add `copilot-cloud`. The alternative, reusing
   `copilot` with a flag, mixes local CLI history and cloud sessions in
   filters and usage.
2. **Machine.** These sessions have no local machine. Proposed: report them
   under a fixed virtual machine id `github-copilot-cloud` per account, so two
   linked machines that both poll upload to the same uid and rely on the
   server's idempotency instead of duplicating sessions. Check that ingest
   tokens bound to a machine (`/v1/link`) allow this; if not, it is a server
   change too.
3. **Opt-in.** Excluded directories and `.firekeeper-ignore` do not apply to
   remote repositories. Proposed: a separate opt-in, an explicit repository
   allowlist in config (`cloud.copilot.repos = ["owner/repo", ...]`), off by
   default, plus the existing per-provider allowlist.
4. **Network.** AGENTS.md says to avoid undocumented network endpoints. This
   task needs one (`/agents/sessions/{id}/logs`) because `gh agent-task view
   --log` only prints a rendered text view. Record the exception in AGENTS.md,
   and say plainly in README and PRIVACY.md that this feature calls a preview
   GitHub endpoint.

## Files

- New: `internal/transcript/copilotcloud/{client,fetch,source,enumerate}.go`,

- Edit: `internal/transcript/event.go`, `docs/event.schema.json` (provider

- Running `firekeeper` with no subcommand must not change and must not make
  network calls.

## Tests

- Parser: table tests over synthetic SSE covering content chunks, tool call
  chunks, tool results, a chunk with both, blank and comment lines, malformed
  JSON (→ `meta`), oversized tool output (truncation marker), and a cut-off
  final line.
- `seq` stability: reading from every returned offset gives the same seqs as
  one full read (reuse `transcripttest` helpers if they fit).
- Client: `httptest.Server` for list, session, and logs, including 401, 404,
  410, timeouts, oversized bodies, and an unknown `state`. Errors must not
  contain the token or transcript text.
- Fetcher: allowlist filtering, skipping live sessions, cache rewrite only on
  change, file permissions, and a provider failure that does not block local
  providers.
- No real network, no real home directory, no real transcripts.

## Open questions

- Host for business and enterprise accounts, and whether `gh` picks it from
  `/user` or config.
- Whether the logs stream is append-only while a session runs.
- Where the initial prompt lives (`event_content`, the task, or the issue).
- Pagination and rate limits for `GET /agents/sessions`.
- Whether to poll on the daemon's interval or a slower one (proposed: at most
  once a minute, with backoff on errors).
