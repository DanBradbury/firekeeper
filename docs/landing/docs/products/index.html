Ways to use Firekeeper

One view of your coding agents, in three places: your terminal, your Mac's menu bar, and your browser. The terminal dashboard is free and open source. Firekeeper Menu Bar and the web dashboard are licensed, opt-in offerings; add them when they help.

Terminal dashboard (CLI)

The Firekeeper CLI (the firekeeper command) is the core of Firekeeper. It is free, open source under Apache 2.0, and developed in the public firekeeper-ai/firekeeper repository. It runs on macOS, Windows 10 1809+ and 11, and Linux (best effort).

Launch your agents the way you always do, then run firekeeper in another terminal. It finds Claude Code, Codex, GitHub Copilot CLI, Kimi Code, OpenCode, Gemini CLI, and Cursor CLI on its own. You need no account, server, wrapper, or background service.

What it does

  • Processes: every running agent with its project, branch, model, and state: working, waiting, or needing your input.
  • Conversation: press c to read a session's chat as it happens, and s to jump to the terminal it runs in.
  • Overview and Usage: token history from your agents' local files, plus the 5-hour and weekly limits where a provider reports them.
  • Scripting: firekeeper snapshot --json prints every discovered session, and firekeeper window breaks the current 5-hour or weekly window down by session.
  • Read-only: it never changes your agents' databases, logs, or launch commands, and the dashboard uploads no conversations.

Install

brew install firekeeper-ai/tap/firekeeper

These commands install only the Firekeeper CLI. They do not install Firekeeper Menu Bar or sign you up for the Hosted dashboard. The quick start has the install script for macOS and Linux, the PowerShell command for Windows, and your first session. The CLI is also what connects a machine to the web dashboard, described below.

Firekeeper Menu Bar

Firekeeper Menu Bar is a licensed macOS app. It is not part of the open-source CLI, and the terminal dashboard does not need it. More about Firekeeper Menu Bar.

It puts your agents in the macOS menu bar. Click its icon to open a panel with every running session; you do not need a terminal window open to keep an eye on them.

Download for macOS (.dmg)

Requires macOS 13 or later and the firekeeper CLI. Looking for an older version? See all Mac app releases.

What it does

  • Every agent at a glance: each session sits under its project, with its task, state, and how long it has run. Subagents nest under the session that started them.
  • Back to the terminal: click a session and the terminal it runs in comes to the front: iTerm2, Terminal, or Ghostty.
  • Know when it needs you: the menu bar icon shows how many agents are waiting for your input.
  • Limits in view: your 5-hour and weekly limits, and how much of each window is left, as your agents report them on this Mac.
  • Your own panel: add, resize, and reorder widgets (limits per provider, live agents, the last 24 hours, recent sessions). Right-click the menu bar icon and choose Edit panel.
  • Filter: press ⌘K in the panel to filter sessions by project, agent, or branch.
  • Usage reviews: right-click a provider's usage to export its 5-hour or weekly window as an HTML page.

Install

  1. Install the CLI first, if you have not (see above). The app reads sessions through it.
  2. Download the DMG, open it, and drag Firekeeper to Applications.
  3. Open Firekeeper from Applications. Enter the license key from the email you received after buying.
  4. The first time you click a session, macOS asks permission to control your terminal. Allow it so the app can bring that terminal forward.

The app checks for a new version when it starts and every six hours. When one is ready, the panel shows Update now. Like the CLI, it is read-only and works locally: it uploads nothing.

Web dashboard

The web dashboard is the browser UI for browsing, searching, and charting sessions reported to Firekeeper Server or the Hosted dashboard. It keeps your agent history in one place, from every machine you link. It is licensed and optional: the terminal dashboard and Firekeeper Menu Bar work without it.

Three ways to run it

  • Free local mode: you run Firekeeper Server on this machine, on loopback, for one user, with no license key. Every dashboard feature works. See Firekeeper Server.
  • Self-hosted Firekeeper Server: you run it on a server you control. A Personal, Team, or Enterprise license is required for remote or shared use.
  • Hosted dashboard: we run it at dashboard.firekeeper.ai. Buy a license, open the signup link emailed to the license address, sign in, then run firekeeper login. See Hosted dashboard.

What it does

  • Overview: agent time, tokens, merged pull requests, and estimated spend for the last 7 days or 4 weeks, against the period before, with daily goals.
  • Sessions: every session from every machine, newest first. Search the full text of your transcripts and filter by machine, agent, project, or state. Filtered views keep their filters in the address, so you can share them.
  • Transcripts: read any session's conversation, with token counts on each event, and export it as a standalone HTML page.
  • Usage: daily tokens by model for 7, 30, or 90 days, totals by project, and an estimated cost from providers' list prices.
  • Skills: which agent skills your sessions used, and how often.
  • Machines: each linked computer and whether it is reporting.

Connect a machine

The CLI sends history to a server only after you link the machine and choose which agents to send. For the Hosted dashboard, buy a license and sign in with your emailed signup link first (existing customers can sign in), then run:

firekeeper login                      # approve this machine in your browser (Hosted dashboard)
firekeeper login --server URL         # or link to a self-hosted Firekeeper Server
firekeeper backfill --all --dry-run   # see what would be sent; uploads nothing
firekeeper backfill --all             # confirm, then send past sessions
firekeeper daemon install             # keep sending new sessions in the background

With no --server, firekeeper login links this machine to the Hosted dashboard. firekeeper whoami shows which account and server this machine reports to. firekeeper logout unlinks it.

Read before you upload. Uploads include session metadata and full transcripts. Every event goes through redaction first, but redaction is best effort, and whoever operates the server can read what you send; on the Hosted dashboard that is Lucky Daisy. See what is uploaded and what is not caught and the reporting reference.

Prefer to keep it on your own hardware? firekeeper serve starts the same web dashboard on this machine through the separate firekeeper-server program, free in free local mode. A shared, self-hosted server for a team needs a license. See pricing.
