Conversation

Read the reply. Jump to the terminal.

No more tab hunting. Select a session and press c to read its available prompts and replies, following new messages live. Press Esc to return.

Press s to focus the terminal holding that session: Ghostty, Terminal.app, and iTerm2 on macOS. On Windows it raises the terminal window; you pick the tab. Reply and approve tool calls in the agent's own terminal.

Usage

Understand usage

Local totals, provider limits, side by side. Compare local token history by model for Codex, Copilot CLI, Kimi Code, and Claude Code. See provider limits where available, separately from local totals.

Every session also gets a per-session token breakdown: input, output, cache read, and cache write. Understand the data sources.

Also in the box

Nothing to configure

No login, server, or daemon for the local dashboard. Quitting Firekeeper leaves your agents running.

Read-only on provider data

Firekeeper never changes your agents' databases, logs, or launch commands.

Ignore whole repos

A repository containing .firekeeper-ignore, or an excluded directory, is never read.

Sessions as JSON

firekeeper snapshot --json prints every discovered session for your own scripts.

Keys for everything

Tab switches Processes, Overview, and Usage. ? lists every key, q quits.

Verified installs

The install scripts check the binary against the release's SHA-256 checksums. No sudo or admin rights.

Optional · Reporting

Stay local. Add a web dashboard only if you need it.

The terminal dashboard is complete on its own. Sending history to a server is a separate opt-in workflow: backfill and the daemon read your agents' local history, redact it, and upload it to the dashboard server you name, over an open API.

Preview first with firekeeper backfill --all --dry-run; it uploads nothing. If you enable uploads, session metadata and full transcripts go through best-effort redaction, and the server's operator can read them. Reporting guide.

Your transcripts, your rules

The terminal dashboard reads provider data locally and uploads no conversations. Provider usage lookups and release checks can contact the network. Transcript reporting is separate and opt-in.

Opt-in per provider

An unconfigured report or daemon sends nothing. You name each provider you allow.

Redacted first

Every event passes through redaction before it leaves the machine.

You pick the server

Uploads go only to the server you name, over HTTPS unless it is on this machine, with a token bound to this machine.

Plain talk: redaction is best effort, and whoever operates a server can read what is uploaded. Read what is uploaded and what is not caught before you turn uploads on.

Install

All releases

macOSHomebrew · recommended

$brew install DanBradbury/tap/firekeeper

Upgrade later with brew upgrade firekeeper. No Homebrew? Use the macOS / Linux script below.

macOS / LinuxInstall script

$curl -fsSL https://raw.githubusercontent.com/DanBradbury/firekeeper/main/install.sh | sh

Installs to ~/.local/bin without sudo and checks the binary against the release's SHA-256 checksums. Command not found?

WindowsPowerShell 5.1 or 7

>irm https://raw.githubusercontent.com/DanBradbury/firekeeper/main/install.ps1 | iex

Installs to %LOCALAPPDATA%\Programs\firekeeper, adds it to your user PATH, needs no administrator rights. Binaries are not code-signed. s raises the terminal window but not the tab. What differs on Windows.

From sourceGo 1.26+

$go install github.com/DanBradbury/firekeeper@latest

Builds from source report their version as dev and never check for updates.
