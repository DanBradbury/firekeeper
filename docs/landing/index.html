Know where your attention is needed

One agent or several, across projects and terminal tabs: see their latest observable state, inspect a reply, and return to the right terminal to keep working.

See what is running

A keyboard-driven terminal UI finds your agent processes, groups each with its children, and shows state, model, working directory, Git branch, and tokens.

Jump to the session

Press s to focus the terminal holding a session. Supports Ghostty, Terminal.app, and iTerm2 on macOS. On Windows it raises the terminal window; you pick the tab.

Read the conversation

Select a session and press c to read its available prompts and replies, following new messages live. Press Esc to return. Reply and approve tool calls in the agent's own terminal.

Understand usage

Compare local token history by model for Codex, Copilot CLI, Kimi Code, and Claude Code. See provider limits where available, separately from local totals. Understand the data sources.

Send history to a server

Optional. backfill and the daemon read your agents' local history, redact it, and upload it to a dashboard server over an open API. You choose the providers.

Install Firekeeper

Choose one method for your system. Prebuilt binaries need no Go toolchain. Then start your agents as usual and open Firekeeper in another terminal.

brew install DanBradbury/tap/firekeeper

For macOS with Homebrew already installed. No Homebrew? Use the macOS / Linux script tab. Upgrade later with brew upgrade firekeeper.

curl -fsSL https://raw.githubusercontent.com/DanBradbury/firekeeper/main/install.sh | sh

Installs to ~/.local/bin without sudo and checks the binary against the release's SHA-256 checksums. Follow the installer's PATH hint before running firekeeper. Command not found?

irm https://raw.githubusercontent.com/DanBradbury/firekeeper/main/install.ps1 | iex

Run in Windows PowerShell 5.1 or PowerShell 7. Installs firekeeper.exe to %LOCALAPPDATA%\Programs\firekeeper (override with FIREKEEPER_INSTALL_DIR), adds it to your user PATH, needs no administrator rights, and verifies the download against the release's SHA-256 checksums. Pin a release by running $env:FIREKEEPER_VERSION = 'vX.Y.Z' first. The binaries are not code-signed.

Verify first: read the script or check the zip yourself

The one-liner runs the script on main, and its checksum check uses checksums.txt from the same release, which proves integrity, not authenticity. To read what you run first, pin the script to a release tag:

$v = 'v0.8.0'
Invoke-WebRequest "https://raw.githubusercontent.com/DanBradbury/firekeeper/$v/install.ps1" -OutFile install.ps1 -UseBasicParsing
notepad .\install.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -Version $v

-ExecutionPolicy Bypass applies to that one process; never Set-ExecutionPolicy Unrestricted. Or download firekeeper_0.8.0_windows_amd64.zip (or _arm64) and checksums.txt from the release and compare (Get-FileHash -Algorithm SHA256 .\firekeeper_0.8.0_windows_amd64.zip).Hash with its line before unzipping. Full steps.

Windows is supported with limits and has had the least real-world use: s raises the terminal window but not the tab, and Codex runtimes are matched to threads by directory and time. See what differs on Windows.

go install github.com/DanBradbury/firekeeper@latest

Requires Go 1.26 or newer. Add your Go bin directory (GOBIN, or $(go env GOPATH)/bin by default) to PATH. Builds from source report their version as dev and never check for updates.

The script commands download and execute code. Prefer to inspect the scripts or download a release yourself? See verification, version pinning, and manual installation. Read the installation steps without tabs.

macOS (Apple Silicon and Intel) is the main target. Windows 10 1809+ and 11 (amd64 and arm64) are supported with limitations. Linux (amd64 and arm64) is best effort.

Your first session, in three steps

Once installed, there is nothing to configure for the local dashboard. No login, server, or daemon needed.

  1. Start an agent as usual

    Open your project and launch any supported agent with its normal command and sign-in. Already have agents running? Leave them running. Firekeeper does not install or launch them.

  2. Open Firekeeper beside it

    In another terminal window, tab, or pane on the same machine, run this from any directory:

    firekeeper

    The Processes view should show your agents within a couple of seconds, along with the project, state, model, and token data it can read.

  3. Select a session and read its latest reply

    Use Up/Down to select, c to open the conversation, and Esc to return. Press s to switch terminals on macOS or Windows; reply in the agent itself. Quitting Firekeeper leaves your agents running.

    Tab Processes / Overview / Usage ? all keys q quit from a main view

Nothing showing up? Check missing sessions. On Windows, switching raises the terminal window, not the tab; on Linux, use your terminal's controls. See the everyday workflow guide for more.

Stay local. Add reporting only if you need it.

Your transcripts, your rules

The terminal dashboard reads provider data locally and uploads no conversations. Provider usage lookups and release checks can contact the network. Transcript reporting is separate and opt-in.

Opt-in per provider

An unconfigured report or daemon sends nothing. You name each provider you allow.

Redacted first

Every event passes through redaction before it leaves the machine.

Ignore whole repos

A repository containing .firekeeper-ignore, or an excluded directory, is never read.

Read-only on provider data

Firekeeper never changes your agents' databases, logs, or launch commands.

You pick the server

Uploads go only to the server you name, over HTTPS unless it is on this machine, with a token bound to this machine.

Plain talk: redaction is best effort, and whoever operates a server can read what is uploaded. Read what is uploaded and what is not caught before you turn uploads on.

The command line

Plain firekeeper opens the dashboard. Everything else is an explicit subcommand.
